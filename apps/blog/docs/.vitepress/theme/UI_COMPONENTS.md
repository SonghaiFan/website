# Blog UI controls

- `SiteControls.vue` owns theme and language. Each is a single 36 px icon button with no outline: the theme button shows the current mode (moon or sun), the language button shows the language you would switch to ("EN" or "中"). Both have an accessible label and a title tooltip. Native VitePress appearance and translation controls stay hidden in `custom.css`.
- The nav is one sheet of frosted glass: `.VPNavBar` carries the page colour at 72% with `saturate(180%) blur(20px)`, every layer VitePress paints inside it is transparent, and one 1px hairline runs along its foot (the title block's own short rule is gone). The sidebar's top strip under the nav is transparent too, so whatever scrolls beneath reads through the glass. The glass is on the bar, not on `.VPNav`: a backdrop-filter there would trap the fixed mobile menu inside the 64px bar. On phones VitePress doesn't fix the nav to the top, so the glass mostly shows on desktop.
- The nav bar reads: brand icon (links to the unified Blog home), then search icon with ⌘K, theme, language, and f's avatar linking to the external chat site with VitePress's external-link icon. The home has Note and Project filters, kept in `?type=`. On the home page the nav search icon is hidden (still mounted, so ⌘K opens the full-text modal).
- The nav language button is the only translation control (the meta line has no "阅读中文版" link). On articles without a paired translation, switching language opens that language's Blog home. Paired articles use `translationUrl` and keep `?view=cards`; the Blog home keeps its `?type=` and `?q=` filters.
- `Layout.vue` owns the article header: title first, then one metadata line (date · reading time · tags · Text/Cards). Meta line layout: date · reading time, then tags as one group (`#python  #matplotlib` — the `#` sets them apart, so no `·` before them and nothing stranded when they wrap), then the actions (card view, share) as a small group pushed to the end of the line with no `·`. Items are centre-aligned (icons have no baseline), with one fixed 2.5px lift on the actions for this font's metrics; icon hover backgrounds are full circles. On phones: date · reading time … actions on the first line, tags on their own line below. Text/Cards is a small Lucide icon (`gallery-horizontal-end` from `@lucide/vue`, cards stacked sideways as the deck swipes) at the end of that line (a 28px target around a 16px icon, lifted onto the text's centre line; aria-label and tooltip "卡片阅读" / "Read as cards"). In card view the way back is the deck's own "← 返回全文". It also owns the view state and URL history.
- The stage script adds `date` (from frontmatter or a dated file name) and `readingMinutes` to each article.
- The sidebar's current-article bar is `SidebarMarker.vue` (in the `sidebar-nav-before` slot), not a border: one 2 px bar in the gutter 12 px left of the active item that glides to it and takes its height (360 ms, the deck's curve) when you move between articles. The active item keeps exactly the same box as the others, so highlighting never changes how a title wraps. Its first placement does not animate.
- No `#` anchor beside article headings (`.header-anchor` hidden): the outline already links every section. Headings keep their ids, so the outline, search hits and `#section` links still work.
- Article pages keep VitePress's two desktop indexes: all articles in the left sidebar, and this article's outline (h2–h3, "本页目录" / "On this page") on the right from 1280 px. The outline is a plain list with no rail: the active heading turns full ink (220 ms) and a short 2×14 px bar glides to it (360 ms, the deck's curve) in the 12 px gutter left of the text, so the outline needs no inset and its text lines up with its title; long headings wrap and is hidden in card view. The local nav bar that VitePress shows under the nav below 1280 px is hidden. Articles use a 700 px reading column, and separate sections with whitespace rather than rules. Images with no Obsidian size (`![[x.png]]`) are capped at `min(62vh, 520px)` tall. A size set in Obsidian (`|640`, `|640x480`) is used exactly as written and only shrinks to fit the column. A standalone image with real alt text gets a caption (`图：…` on Chinese pages); alt text that is only a file name is ignored.

## Card motion (`CardDeck.vue`)

**Full screen.** Card view fills everything under the nav (`position: fixed; inset: nav 0 0 0`) on phone and desktop: a top bar (← 返回全文 on the left; PNG / ZIP download icons on the right), the stage, a bottom bar (← n / N →). The page underneath is locked (`html.cards-open`: no scroll, no overscroll) and the deck takes every touch (`touch-action: none`), so there is nothing to scroll vertically and a swipe can only mean sideways. The card is fitted into the stage both ways (contain, up to 1:1) and centred; its slot is exactly card-sized so the shadow sits on the card. Besides dragging: one two-finger horizontal trackpad swipe turns one card, ←/→ work without focusing the card, Esc returns to the text.

The deck is a stack of paper, and it has **one position**. `pos` is a continuous place in the deck in card-steps (2.3 = 30% of the way from the third card to the fourth). Dragging, the glide after release, the arrow buttons and the keyboard only ever change `pos`; `place(rel)` is the one function that turns it into where each card sits. There is no hand-off between a drag and a transition, because there is only one motion. `pos` is never wrapped (only the page shown in a slot is), so crossing the end of the deck never sends a card the long way round.

- **Geometry**: the top card is pulled off to the left and uncovers the one beneath, which rises from 28 px lower and `scale(.95)`. Going back, the card returns from the left onto the top. Four slots are rendered (leaving, top, beneath, one more under that), keyed by unwrapped position, so nothing appears or disappears while the stack advances. Paint order follows position, so two cards never swap order mid-move.
- **No opacity on the stack.** A pulled card is opaque for as long as it overlaps the card beneath (it travels 1.04 card widths), and fades only in the last 8%. A half-transparent card over another is two pages of text at once.
- **Drag**: one to one with the finger, no rubber band (the deck loops, so there is no end to signal). Transforms are written straight to the slots; Vue re-renders only when the set of slots changes.
- **Release**: velocity from the last few readings, smoothed; the release looks 300 ms ahead (a card is ~500 px wide, so a short flick needs that much) and moves at most one card past the drag. Then a 560 ms quart-out glide from wherever the deck is.
- **Interruptible**: a click or a grab during a glide starts from the live position; repeated clicks add up (they step from the glide's target, not from where it is now).
- The stage sits at `z-index: 26`, above the desktop sidebar (25) and below the nav (30), so a pulled card passes over the sidebar instead of being cut by its edge. One static shadow on the slot (not the card, so PNG exports are clean).
- **PNG/ZIP export**: rasterize the same 1080 × 1350 card DOM shown in preview. Eager-load and decode source images, embed them as PNG data URLs, then decode those cloned images before capture. If an image fails or times out after 20 seconds, abort the export with an error instead of downloading a card with missing imagery.
- Card view hides both side panels (all articles, outline) and drops the sidebar's padding so the deck sits in the middle of the page; the nav's sidebar corner rule goes too. Switching is two steps of plain CSS animation on the real elements (`Layout.vue` puts `view-<phase>` on the layout root): what is on screen leaves (220 ms — sidebar out to the left, outline out to the right, article or deck fading), then the other view arrives (480 ms — panels back from their own edges, article fading in; the deck has its own rise). Not a view transition: that draws the panels' snapshots above the whole page, and the sidebar's top strip (under the nav) covered the nav's title while it slid.
- `prefers-reduced-motion` and PNG/ZIP export skip the glide and jump straight to the card.

## Text view motion (`Layout.vue`, `custom.css`)

- Same-page anchors (headings, footnotes, in-article `#` links) scroll smoothly, at any distance. Smooth scrolling is switched on only for that click and cleared on `scrollend`, so page-to-page navigation still lands at the top instantly.
- Article links: the underline starts at `--vp-c-text-3`, then darkens and moves 0.06em closer to the text on hover (220 ms). Sidebar titles, nav links and prev/next titles share the same 220 ms colour ease.
- Article images still downloading start transparent and fade in over 360 ms when they load. The class is added by JS only, so images never stay hidden without it.

## Search

- **Home** (`BlogFilter.vue`, `HomeSearch.vue`): the Blog home filters Note and Project entries with `?type=`, including the search results. Old `?type=daily` links map to Note. Search is inline under the filter; with a query, results replace the entry list (period/date and type, "entry › section" with matches marked, and a rendered section or one-line excerpt). Search uses VitePress's local index and options; `/api/search-index.json` supplies public entries, type, and excerpts. ↑↓ select, Enter opens, Esc clears; ⌘K and `/` focus the field. The query stays in `?q=`.
- **Elsewhere** ⌘K opens VitePress's modal.
- **The modal's look** (end of `custom.css`): colours through VitePress's `--vp-local-search-*` variables, the rest by selector. No outlines — the field and the selected result are tinted surfaces; matches are a soft wash (`--vp-c-brand-soft`), not a black block; 720 px wide, 12vh from the top, blurred backdrop; it fades and rises 10 px in (320 ms). Full screen on phones.

## Pull to the neighbouring article (`ArticlePull.vue`, `PostHeader.vue`, `pull-state.js`)

One gesture, mirrored at both ends of an article (order = the sidebar's articles; group headings such as 全部文章, which links home, are not neighbours — the newest article simply has nothing before it).

- **Link inside, hint outside.** Every article has a pull zone above its title and one under its last line, the same height (`--pull-zone`: 80px desktop, 64px phone); the top zone is the page's own top space and the page ends with the bottom zone, so they match to the pixel. Inside each zone is a quiet centred neighbour control (`PullLink.vue`): "上一篇  标题" above the title, "下一篇  标题" under the last line (title a shade stronger, truncating). On desktop it is a button that starts the article glide and navigates only at hand-off; the mouse wheel only scrolls normally. On phones it is a link, and touch-pulling at either edge reveals the hint (`PullHint.vue`): it sits just past the page edge — edge, 24px, "[F] 继续上滑" (under the end) / "[F] 继续下滑" (over the top), 24px, then the neighbour — on a fixed layer that moves with the pull, so it only comes into view when a pull reveals it and never adds scroll height. Past the threshold the verb becomes 松开阅读 (both verbs share one cell, so the centred line never shifts). The hint belongs to no page and fades out during the glide. The newest article has no top link; the oldest ends with `· · ·`.
- **The F mark** (`PullMark.vue`, the single open stroke from `f-icon-curve.svg`) leads each hint. At rest it is a faint ghost of the signature; while pulling, the signature is written in ink along its own length in proportion to the pull (`pathLength=1`, so progress = dash offset), finished exactly at the threshold. Springing back unwrites it; momentum (capped at 60%) never finishes it.
- **Pull**: at the end, pushing on lifts the article column and the hint, then the next article, rise from the bottom edge; at the top, pulling back lowers the column and the hint, then the previous article's title block, come down (a window onto its top that shows only what is above the hint). Damped: visual pull = 240 × (1 − e^(−0.5·input/240)).
- **Let go / click**: a phone touch release short of 75 px springs back (420 ms); past it, the neighbour glides in (560 ms). Desktop link clicks begin the same glide at that threshold. Both directions land at the **top** of that article — the next one rising into place; for the previous one this article slides on down and out of view while the previous title glides to its place and the window opens behind it — and the page becomes that article (URL, tab title, sidebar, outline). Normal history.
- **Scroll ownership**: mouse wheel and trackpad scrolling never trigger article navigation. Only touch input on phone-sized layouts can pull through an article edge; desktop readers use the visible previous/next links.
- While pulled the page itself doesn't scroll; the browser's rubber-band is off on articles (`html.pull-to-next`). Only the article column moves; sidebar and outline stay.
- **Previews** are the neighbours' page modules rendered with the same `PostHeader`, `.vp-doc` and end-hint markup over the article column (ids stripped). The entering preview's opaque surface also covers its previous-link zone above the title. During a next-article glide, the outgoing column moves an additional `--post-end-space` plus any distance needed to clear its last line from the viewport before hand-off; its tail cannot overlap the entering link or disappear on the final frame. Their own hints are hidden while pulling and fade in during the glide, so only this article's hint speaks during the pull and the hand-off frame still matches.

## Icons

Every icon on the blog is Lucide.

- Ours come from `@lucide/vue` (ISC), one imported component each, all at one stroke weight, `ICON_STROKE` (1.75) in `icons.js`: theme `sun` / `moon` (17px, `SiteControls.vue`); home search `search` (18), `layout-list` (16), `x` (16) (`HomeSearch.vue`); card view `arrow-left` for 返回全文 (16), `arrow-left` / `arrow-right` for previous / next (18), and the downloads as two icon buttons — `image-down` for this card as PNG, `folder-down` for the whole deck as ZIP (18; tooltip and aria-label 下载这张 PNG / 下载整组 ZIP) (`CardDeck.vue`); `gallery-horizontal-end` for Text → Cards (16, `PostHeader.vue`). They inherit `currentColor`.
- VitePress's own icons (nav search, the ↗ on external links, mobile menu, search modal) are Lucide already, drawn by VitePress at stroke 2; they are left as they are.
- Not icons, so not Lucide: the EN / 中 language label, `· · ·`, and the F signature (`PullMark.vue`), which is the brand mark.
- `lucide-vue-next` is the deprecated name of the same project; don't add it.

## Projects

Project pages are written in the vault (`Blog/projects`, `Blog/en/projects`) and staged by the same pipeline as posts, so they are `blogPost` pages too, with `project: true`. They get the article layout, header, outline, card view and pull navigation. Where a post shows its date, `PostHeader` shows the `period` (2021–2026), and `PullLink` says 上一个/下一个. Projects appear in the unified Blog home; the old `/projects` and `/zh/projects` indexes redirect to its Project filter. Detail URLs and their ordered sidebar remain. `public/api/projects.json` (used by the songhai.site assistant) is still built from the same pages.
